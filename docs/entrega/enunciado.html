Contexto

Você recebeu dois arquivos de uma corretora fictícia. Sua missão é criar um projeto dbt funcional que transforme esses dados brutos em modelos analíticos confiáveis — com estrutura de camadas, testes e documentação.

O critério principal é simples: o projeto roda limpo com dbt run && dbt test.

Dados de entrada

Seeds do projeto

Adicione os dois arquivos na pasta seeds/ e carregue com dbt seed.

transactions.csv compras e vendas de ativos por cliente
clients.csv cadastro de clientes
⚠ Os arquivos contêm problemas intencionais de qualidade. Esperamos que seus testes dbt os sinalizem — não que você limpe os dados manualmente.
Estrutura esperada

Três camadas de modelos

models/ staging/ stg_transactions.sql   -- limpeza e tipagem da fonte stg_clients.sql       -- limpeza e tipagem da fonte intermediate/ int_transactions.sql   -- joins e regras de negócio marts/ fact_transactions.sql   -- tabela fato de transações dim_clients.sql       -- dimensão de clientes mart_client_portfolio.sql  -- posição atual por cliente/ativo tests/ assert_no_negative_position.sql  -- teste singular obrigatório
Requisitos
  • 1 Crie os modelos de staging com renomeação de colunas para snake_case, tipos corretos e filtro de registros inválidos.
  • 2 Crie o modelo mart_client_portfolio que calcula a posição líquida de cada cliente por ativo (BUY − SELL em quantidade e valor financeiro).
  • 3 Adicione testes genéricos nos modelos via schema.yml: not_null, unique e accepted_values onde fizer sentido.
  • 4 Crie o teste singular assert_no_negative_position.sql que retorna linhas onde a posição líquida de algum cliente seja negativa.
  • 5 Documente todos os modelos no schema.yml com descrição de cada coluna.
  • 6 Transforme o modelo fact_transactions em incremental, usando transaction_date como chave de controle. bônus
  • 7 Crie uma macro reutilizável para qualquer lógica repetida em mais de um modelo. bônus
  • 8 Grave um vídeo de no máximo 5 minutos explicando o que foi feito: decisões tomadas, estrutura do projeto e como rodar. Envie o link junto com o repositório. obrigatório
Como vamos validar

Três comandos. Tudo tem que passar.

dbt seed carrega os CSVs
dbt run  builda todos os modelos sem erro
dbt test roda todos os testes — o teste singular deve detectar o problema nos dados
Se o projeto não rodar a partir do README sem precisar de ajuda externa, a entrega não será avaliada.
Publique o projeto em um repositório no seu GitHub e envie o link para fernando@clubedovalor.com.br.
